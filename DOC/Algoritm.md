# Алгоритм работы программы — простыми словами

Документ описывает, что программа делает шаг за шагом: как она смотрит на систему, что
запоминает и как возвращает всё назад. Он написан без имён функций и без имён файлов:
встречаются только команды командной строки и переменные настроек (`prelaunch`,
`prelaunch-args`, `prelaunch-timeout`, `AutoSave`, `AutoRestoreDelay`, `Layouts`,
`settle-wait`) — ровно те слова, которые пользователь видит и может менять сам.

---

## 1. Общая идея

У программы две рабочие операции и несколько служебных.

* `save` — «посмотреть и записать»: программа обходит все окна на всех виртуальных рабочих
  столах и складывает их описание в один текстовый слепок.
* `restore` — «привести к записанному»: программа читает слепок, ставит уже открытые окна на
  свои места (стол, координаты, размер, состояние, порядок наложения), а приложения, окон
  которых нет, запускает и тоже расставляет.
* служебные команды: `AutoSave` и `AutoRestore` ставят задачи в Планировщик заданий,
  `Uninstall` их снимает, `--list` показывает, что программа видит прямо сейчас,
  `--help` и `--version` печатают справку и версию.

Ключевая мысль: слепок — это не «снимок экрана» и не список процессов, а набор **записей об
окнах**. Именно окно является единицей хранения, потому что пользователь помнит не «процесс
такой-то», а «вот это окно стояло здесь, на этом столе». Приложение, у которого не осталось
окна, восстанавливается запуском; приложение, у которого окно есть, не запускается второй раз,
а просто переставляется.

За один запуск выполняется ровно одно действие. `save restore`, `--list --version`,
`AutoSave restore` — это ошибка разбора командной строки, а не «сделай два дела подряд»:
так случайная опечатка в скрипте не приведёт к неожиданным изменениям на экране.

## 2. Что программа считает окном

Программа перебирает верхнеуровневые окна системы — их сотни, — и оставляет только те,
которые имеет смысл помнить. Отбрасываются:

* невидимые окна;
* служебные окна-панели (палитры, подсказки, IME, окна с пометкой «вспомогательное»);
* окна, у которых есть «владелец» — кроме диалогов с заголовком: диалог — нормальное окно,
  а вот скрытый клон или панель предпросмотра владельцем как раз и выдаёт себя;
* окна без заголовка — кроме окон Проводника, рамок приложений из Microsoft Store и диалогов;
* пустые рамки приложений из Microsoft Store (оболочка держит по одной такой на каждый
  монитор; содержимого в них нет);
* служебные окна оболочки: рабочий стол, панели задач, системные контейнеры;
* «унаследованно накрытые» окна — те, которые накрыты не потому, что лежат на другом
  виртуальном столе, а потому что их накрыло родительское окно.

Отдельно есть два вида «накрытых» окон, и оба важны:

* окно **на другом виртуальном столе** — оно живое, просто сейчас не показано. Именно ради
  таких окон программа и написана, поэтому они сохраняются обязательно;
* окно, которое **спрятало само приложение** (приостановленное приложение из Microsoft
  Store) — оно тоже сохраняется, с пометкой «спрятано приложением». При восстановлении его
  сначала придётся «разбудить» обычной активацией, поэтому пометка полезна.

Для каждого оставшегося окна собираются сведения:

* номер в порядке наложения (нулевой — самое верхнее окно на экране);
* заголовок и класс окна;
* процесс-владелец, путь к его программе и командная строка (её читает система, и она
  недоступна для защищённых и завершающихся процессов — тогда путь остаётся пустым);
* папка, если окно принадлежит Проводнику;
* идентификатор приложения магазина, если он есть;
* состояние окна: обычное, развёрнутое или свёрнутое;
* «нормальные» координаты окна и монитор, на котором оно стоит;
* адрес страницы — только у браузеров;
* признак «окно было открыто от администратора».

Почему координаты берутся «нормальные», а не текущие: у развёрнутого окна текущие границы —
это весь монитор, у свёрнутого — служебные минус тридцать две тысячи по обеим осям. Ни то,
ни другое не говорит, куда окно вернётся, если его развернуть или восстановить. Поэтому
запоминается та позиция, которую окно занимает в обычном состоянии, — её и вернёт
восстановление.

Почему координаты хранятся дважды: абсолютные (для сверки и диагностики) и в виде смещения
от угла **своего** монитора. Восстановление идёт по смещению: если мониторы поменялись
местами, основной монитор стал другим или изменилось разрешение, окно всё равно встанет в
тот же угол «своего» монитора, а не уедет за край экрана. При смене масштаба (DPI) смещение
пересчитывается.

## 3. Как программа понимает виртуальные рабочие столы

Список столов программа берёт из реестра: там для каждого стола есть номер, постоянный
идентификатор (GUID) и имя. Если реестр прочитать не удалось, список восстанавливается
«по окнам» — приблизительно, о чём программа честно предупреждает.

Имя стола — главный ключ, потому что человек, давая столу имя, связывает его с тем, что на
нём открыто. Номер — запасной ключ («третий слева»). GUID переживает переименование и
перестановку, но ничего не говорит о содержимом, поэтому он замыкает цепочку.

Текущий стол определяется по очереди несколькими способами, и в отчёте видно, какой сработал:

1. окно в фокусе;
2. окно консоли, из которой запущена программа;
3. голосование по окнам (учитываются видимые, не «накрытые» окна; побеждает стол, где их
   больше);
4. окна оболочки — рабочий стол и панели задач;
5. значение в реестре (на актуальных сборках Windows его обычно уже нет).

Если ни один способ не сработал, программа пишет «не определён» и продолжает работу: это
штатная ситуация на пустом рабочем столе.

Отдельная тонкость — приложения, помеченные «показывать на всех рабочих столах»
(закреплённые на всех столах). Их окна не принадлежат ни одному столу: система отдаёт для
них служебный идентификатор, которого нет в списке столов. Программа распознаёт такие окна
и запоминает их отдельно: их не надо переносить между столами (они и так видны везде), а при
восстановлении не надо запускать второй раз, если приложение уже работает.

## 4. Снятие слепка: `save`

Порядок работы:

1. **Настройки.** Читается переменная `Layouts` — сколько рабочих версий слепка держать
   рядом. Если файла настроек нет или он повреждён, берутся значения по умолчанию, а работа
   продолжается: отсутствие настроек — не повод остаться без слепка.
2. **Столы и мониторы.** Читается список столов и текущий стол, перечисляются мониторы:
   имя устройства, положение, рабочая область и масштаб. Мониторы нужны, чтобы записать
   смещение каждого окна от угла своего монитора.
3. **Окна.** Собираются все окна-кандидаты (раздел 2). Для каждого определяется стол: если
   окно на столе, которого нет в списке (это признак закреплённого окна), оно помечается как
   «показывать на всех столах» и получает номер того стола, на котором его видно.
4. **Адрес страницы.** У окон браузеров через средство доступности Windows читается адрес
   активной вкладки. В командной строке процесса его нет — он живёт в профиле браузера, —
   поэтому это единственный способ потом открыть ту же страницу.
5. **Права окна.** Для каждого окна выясняется, был ли его процесс запущен от администратора.
   Результат — пометка «окно было открыто от администратора». Если выяснить не удалось,
   окно считается обычным: попытка запуска либо сработает, либо даст понятную ошибку.
6. **Сортировка.** Записи раскладываются по номеру стола, а внутри стола — сверху вниз по
   порядку наложения. Порядок в файле получается «человеческим»: его можно читать глазами
   и править руками.
7. **Дубли.** Если два окна дают одинаковые программу, класс, заголовок и почти одинаковые
   координаты на одном столе, остаётся одна запись. Так отбрасываются служебные копии окна
   (панель предпросмотра, скрытый клон), а не теряется настоящая запись. В отчёте видно,
   сколько дублей пропущено — и только если пропускать было что.
8. **Сравнение с прошлым слепком.** Перед записью свежий слепок сравнивается с тем, что уже
   лежит на диске: столы, мониторы, разрешение экрана и все поля окон как множество (порядок
   записей не важен). Не сравниваются порядок наложения — он меняется от каждого клика по
   окну — и метка времени. Если ничего не изменилось, файл не переписывается, и программа
   так и говорит: «Слепок не изменился с … — файл не переписан». Это важно для `AutoSave`:
   задача срабатывает каждые несколько минут, и без такой проверки диск писался бы впустую.
9. **Запись.** Файл пишется не поверх старого, а сначала во временный, и только потом
   занимает место прежнего. Так обрыв питания в момент записи не оставит половину слепка.
10. **Ротация и защищённые копии.** Прежний слепок становится рабочей версией с датой и
    временем в имени; самых новых рабочих версий остаётся столько, сколько задано в `Layouts`
    (по умолчанию три, допустимо от одного до двадцати), остальные удаляются.
11. **Смена конфигурации.** Если набор мониторов (состав, разрешение, положение) или набор
    столов изменился, прежний слепок дополнительно сохраняется как «прежняя конфигурация»:
    старая цепочка сдвигается, самый старый экземпляр пропадает. Это отдельные защищённые
    копии, и чистка рабочих версий их не трогает. Движок здесь именно `save`, потому что
    смену конфигурации видит он: он сравнивает свежий слепок с прежним. О событии программа
    сообщает и без подробного режима — это не «ещё одна копия», а точка возврата.
12. **Самопроверка.** В подробном режиме (`--verbose`) только что записанный файл читается
    обратно и сравнивается с тем, что писали. Расхождение означало бы ошибку экранирования
    (например, точку с запятой или перевод строки в заголовке) — такую ошибку лучше увидеть
    при сохранении, чем при восстановлении.

Что попадает в слепок: список столов (номер, идентификатор, имя), список мониторов и по
записи на каждое окно — стол, пометка «показывать на всех столах», номер в порядке
наложения, путь к программе, командная строка, класс, папка Проводника, заголовок,
идентификатор приложения магазина, монитор-якорь, координаты (абсолютные и смещение от
угла монитора), состояние, адрес страницы и пометка «от администратора».

Записи без единого опознавательного признака (нет ни программы, ни идентификатора
приложения, ни заголовка, ни класса, ни командной строки, ни папки, ни адреса) при чтении
выбрасываются: иначе пустая запись превращалась бы в строку отчёта «не запускаем» и портила
код возврата. Неизвестные ключи внутри записи игнорируются — файл можно править руками,
добавлять свои пометки и заготовки будущих настроек.

### Защищённые копии

Рядом с рабочими версиями живут копии, у которых в имени не дата, а слово:

* **цепочка дней** — «вчерашний день», «позавчерашний день», «позапозавчерашний день»;
  её двигает `restore` при старте новой сессии;
* **цепочка конфигураций** — «прежняя конфигурация», «прежняя конфигурация 2», «прежняя
  конфигурация 3»; её двигает `save` при смене мониторов или набора столов.

Эти копии не удаляются никогда, даже при `Layouts=1`: иначе откат был бы возможен ровно до
третьего сохранения. Вернуться к ним можно командой `restore --from` с именем нужной копии.

## 5. Восстановление: подготовка

`restore` — самая большая часть работы. Он идёт строго по шагам, и порядок здесь не
случайный: каждое следующее действие опирается на то, что стало известно раньше.

### 5.1. Настройки и слепок

Сначала читаются настройки: `settle-wait` (сколько ждать «успокоения» окон) и
`AutoRestoreDelay` (пауза после раннего запуска браузеров). Сбой чтения настроек не отменяет
восстановление: берутся значения по умолчанию.

Затем читается слепок — либо основной, либо указанный в `--from`:

* имя без диска ищется рядом с программой (так указывают на рабочую версию, «вчерашний
  день» или «прежнюю конфигурацию»);
* путь с диском или сетевым адресом берётся как есть;
* файла нет или он битый — сообщение и код возврата 2, ничего не меняется.

`--from` — это осознанный откат, поэтому при нём не двигается цепочка дней (см. 5.2) и
работает всё остальное.

В отчёте сразу печатается, что прочитано: когда слепок снят, сколько в нём столов,
мониторов и окон. В режиме `--dry-run` добавляется строка, что окна не перемещаются и ничего
не запускается.

### 5.2. Цепочка дней

`restore` — это ещё и начало новой сессии. Поэтому слепок, из которого восстанавливаемся,
копируется во «вчерашний день», прежний «вчерашний» уезжает в «позавчерашний» и так далее
по цепочке из трёх копий.

Признак новой сессии — не время суток, а время загрузки системы: метка «когда снят» в
слепке сравнивается с моментом старта Windows. Слепок, снятый уже после загрузки, — середина
текущей сессии, двигать нечего. Иначе каждые десять минут работы `AutoRestore` съедал бы
историю: «вчерашний день» становился бы «сегодняшним утром».

Цепочка не двигается ещё в трёх случаях: если слепок уже стоит во «вчерашнем дне» (повторный
`restore`), в режиме `--dry-run` (он ничего не меняет) и при `--from` (это возврат к
выбранной копии, а не начало нового дня). Решение в подробном режиме печатается словами,
чтобы не приходилось догадываться.

### 5.3. Предварительная программа: `prelaunch`

Второй монитор часто включается позже компьютера (телевизор), и рабочий стол на него не
приходит, пока это не поправит сторонняя утилита. Поэтому у `restore` есть предварительный
шаг:

* `prelaunch` — путь к такой программе; пустое значение или отсутствие переменной означает
  «ничего не запускать»;
* `prelaunch-args` — аргументы для неё (обычно не нужны: утилита настроена сама);
* `prelaunch-timeout` — сколько секунд ждать, пока окно программы закроют; ноль означает
  «ждать без ограничения».

Пока окно этой программы открыто, восстановление не начинается: иначе раскладка применилась
бы к «недонастроенному» экрану. Ожидание заканчивается, когда видимых окон этой программы не
осталось (процесс при этом может остаться в памяти) либо когда она завершилась, не показав
окна вовсе. Окна считаются по пути к программе, а не по номеру процесса: утилита может
показать окно из уже запущенной копии.

Если программы нет, она не запускается или окно не закрыли за `prelaunch-timeout` секунд,
печатается предупреждение, и работа продолжается без неё. Остаться совсем без
восстановления хуже, чем восстановить на «кривом» экране.

Шаг выполняется только у `restore`. `save` ничего не восстанавливает — он записывает то, что
видно сейчас, и внешняя утилита ему не нужна. `--dry-run` и `--list` этот шаг тоже
пропускают: они ничего не меняют.

### 5.4. Столы: сопоставление «как было» → «как стало»

Для каждого стола из слепка ищется сегодняшний стол, и порядок поиска такой:

1. **по имени** — человек, давая столу имя, связывает его с содержимым, поэтому имя главнее;
2. **по номеру** — если стола с таким именем нет («третий слева»);
3. **по идентификатору** — GUID переживает переименование и перестановку, но о содержимом
   не говорит, поэтому он замыкает цепочку; такая пара помечается «переименован»;
4. **первый стол** — если не нашлось ничего; в отчёте такая пара помечается отдельно
   («целевой стол не найден»).

Имена столов в программе не зашиты. Имя, которого нет в системе, печатается как «имени нет
в системе», а окна такого стола уезжают на первый стол — с отдельным предупреждением в конце
(раздел 10).

### 5.5. Мониторы

Перечисляются мониторы, которые есть сейчас. По ним пересчитывается смещение от угла
монитора: если монитор-якорь отключён, берутся абсолютные координаты; если и они не попадают
ни на один монитор, окно ставится на основной монитор с сохранением относительной позиции;
при смене масштаба смещение пересчитывается.

### 5.6. Ранний запуск браузеров

Браузер при холодном старте сам восстанавливает сессию профиля («продолжить с того же
места»), но делает это не сразу: его окна могут открываться спустя минуту. Если пустить это
на самотёк, восстановление успеет открыть те же адреса второй раз — и получится по два окна.

Поэтому до снятия общего снимка окон программа смотрит, какие браузеры есть в слепке:

* уже запущенный браузер не трогается: его сессия восстановлена при входе в систему;
* незапущенный поднимается **без адреса** и получает несколько секунд (около двух с
  половиной) на восстановление своих окон;
* затем выдерживается пауза `AutoRestoreDelay` секунд, чтобы окна сессии успели появиться
  и попасть в снимок;
* пустые окна, которые браузер открыл сам при старте («новая вкладка»), закрываются: в
  слепке их нет, а на текущем столе они остались бы лишними.

Права при этом те же, что будут при обычном запуске: при повышенном восстановлении браузер
поднимается с правами обычного пользователя, иначе он не увидит профиль пользователя.

Если браузер не поднялся за отведённое время, это не ошибка: дальше он будет запущен обычным
порядком, просто позже.

## 6. Сопоставление: какое живое окно соответствует какой записи

Это самая тонкая часть алгоритма. В слепке лежат записи, в системе — живые окна, и надо
понять, какая запись про какое окно. Ошибка здесь стоит дорого: чужое окно уедет на место
потерянного, а нужное откроется вторым экземпляром.

### 6.1. Снимок живых окон

Собирается снимок всех окон-кандидатов (те же правила, что при `save`), и для каждого окна
определяется его текущий стол. Текущий стол нужен дважды: чтобы разрешать «ничьи» при
сопоставлении и чтобы не звать перенос там, где окно уже на месте.

### 6.2. Адреса страниц у живых браузеров

Если в слепке есть хотя бы одна браузерная запись с адресом, программа читает адрес открытой
страницы у живых окон браузеров. Если адрес прочитать не удалось, делается вторая попытка:
средство доступности могло не успеть, страница могла ещё грузиться.

Зачем: адрес — главный признак содержимого окна браузера. Без него окно сопоставляется
«слепым», и запись может прилипнуть к чужому окну. Это не теория: однажды окно с чужой
страницей уехало на другой стол именно так. А читать адрес, когда в слепке не с чем его
сравнивать, бессмысленно: каждый такой запрос — межпроцессный вызов с таймаутом.

### 6.3. Баллы

Каждая пара «запись ↔ живое окно» получает баллы за совпадение признаков:

* путь к программе — 100;
* идентификатор приложения магазина — 60;
* адрес страницы у браузера — 60;
* класс окна — 50;
* папка Проводника — 40;
* точный заголовок — 40;
* тот же стол — 25 (или 10, если совпадение слабее);
* близкие координаты — 20.

Пара принимается, если набрала 100 баллов (практически это «совпал путь к программе») либо
90 для Проводника (класс плюс папка). Окна одного приложения различаются заголовком, папкой
и координатами.

Два запрета работают даже при большом числе баллов:

* если папка Проводника известна и у записи, и у окна, но они разные — пара не
  рассматривается вовсе;
* если адрес страницы у браузера известен с обеих сторон и отличается — пара отклоняется:
  нужная страница откроется отдельным окном, а чужое окно останется на месте.

### 6.4. Ничьи

Если несколько окон одного приложения дали одинаковый максимальный балл, сидят на **разных**
столах, и ни заголовок, ни папка, ни адрес их не разделяют, пара не создаётся вовсе. В
отчёте появляется строка «неоднозначно: N записей». Окна остаются на своих столах, а записи
уходят в фазу запуска: лишнее окно лучше, чем окно с чужим содержимым на неверном столе.
Время здесь не экономится — окна одного приложения с разных столов не должны меняться
местами.

### 6.5. Проверка переноса между столами

Прежде чем что-либо менять, программа считает, сколько окон вообще потребует переноса на
другой стол. Если такие окна есть, проверяется внутренний интерфейс оболочки Windows,
который только и умеет переносить чужие окна. Документированный способ переносит только окна
собственного процесса, для остальных он отвечает «отказано в доступе» — тихо положиться на
него значило бы оставить окна не на своих столах, а отчёт сделал бы вид, что всё хорошо.

Если проверка не прошла (другая сборка Windows), работа прекращается **до первого
изменения**: программа объясняет причину и возвращает код 6. В режиме `--dry-run` план всё
равно печатается, но код возврата тоже 6: раскладку восстановить не получится.

## 7. Фаза A: уже открытые окна ставятся на место

Для каждой принятой пары выполняется одно и то же:

1. **Координаты.** Из записи берётся смещение от угла монитора и пересчитывается в
   сегодняшние координаты на сегодняшнем мониторе. Если посчитать не удалось (мониторы не
   перечислены), окно считается не восстановленным — с предупреждением.
2. **Состояние и геометрия.** Окно получает сохранённую позицию, размер и состояние
   (обычное, развёрнутое, свёрнутое) одним системным вызовом. Это единственный корректный
   способ вернуть и «нормальную» позицию, и состояние одновременно: если ставить размер и
   разворачивать по отдельности, развёрнутое окно вернётся не туда.
3. **Перенос на стол.** Перенос нужен только окну, которое сейчас не на целевом столе и не
   помечено «показывать на всех столах». Результат проверяется: если окно не оказалось на
   нужном столе, делается до трёх попыток, и только потом в журнал для человека попадает
   причина «перенести не удалось». Окно, которое уже на месте, лишний раз не трогается —
   лишнее движение видно глазом и раздражает.
4. **Порядок наложения.** Окно запоминается для третьей фазы (раздел 9).

В режиме `--dry-run` вместо применения печатается план: заголовок, текущая нормальная
позиция, целевая позиция, целевой стол, состояние, нужен ли перенос, поправки. План строится
теми же расчётами, что и настоящие изменения, поэтому увиденное совпадает с тем, что сделает
настоящий `restore`. Ничего не перемещается и не запускается.

Что делать с окном, которое применить не удалось: сообщение в консоль, запись в журнал для
человека готовой командой запуска и счётчик «не удалось восстановить». Типичные причины —
окно принадлежит приложению, запущенному от администратора (Windows тихо игнорирует
перемещение такого окна из обычного процесса), либо система ответила «отказано в доступе».

### 7.1. Почему окна ждут «успокоения»: `settle-wait`

После входа в систему окна открывает не только программа: Windows возвращает окна папок
(если включено «восстанавливать прежние окна папок при входе»), поднимаются приложения из
автозагрузки, браузеры восстанавливают сессию профиля. Всё это происходит в те же секунды,
что и восстановление раскладки.

Раньше снимок окон брался один раз в начале работы, и запись, чьё окно появилось позже,
считалась потерянной — программа запускала вторую копию приложения. Теперь перед запуском
приложений программа ждёт, пока состав окон перестанет меняться: две секунды без изменений.

Ожидание ограничено переменной `settle-wait` (по умолчанию десять секунд, ноль — не ждать
вовсе, максимум шестьсот). Само ожидание — только подстраховка: перед **каждым** запуском
программа заново смотрит, не открылось ли нужное окно само (раздел 8.2). Поэтому дублей не
будет и при `settle-wait=0` — окна просто могут появиться позже. `--dry-run` не ждёт ничего:
он ничего не меняет.

В подробном режиме видно, как шло ожидание: «окон стало 24 (было 21) — состав ещё меняется»
и итоговое «окна успокоились: ждали 3.5 с».

## 8. Фаза B: запуск приложений, окон которых нет

Записи, для которых не нашлось живого окна, — это приложения, которые надо поднять.
Запускается не «программа вообще», а конкретное окно: с той же папкой, той же страницей или
той же командной строкой.

### 8.1. Что и как запускается

Способ запуска выбирается по записи:

* **Проводник** — открывается по сохранённой папке. Именно папка, а не заголовок, —
  заголовки у окон Проводника повторяются, и папка их различает;
* **приложение из Microsoft Store** — активируется по своему идентификатору;
* **виртуальная машина** — по сохранённому идентификатору машины; внутренняя служебная
  командная строка для повторного запуска не годится, поэтому из неё извлекается нужный
  параметр;
* **браузер** — по адресу страницы, с ключом «открыть новое окно». У Firefox ключ другой, у
  старого Internet Explorer адрес передаётся без ключа;
* **консоль с известной командой** — повторяется именно эта команда (например, «запустить
  командный файл»), в собственной консоли. Так восстановление не забирает консоль у самого
  себя и не закрывает её вместе с собой;
* **остальные** — по сохранённой командной строке, а если её нет — по пути к программе.

Что **не** запускается:

* консоль, в командной строке которой только имя оболочки без аргументов: неизвестно, что в
  ней было запущено, и повторный запуск открыл бы пустое окно;
* браузер, у которого при сохранении не удалось прочитать адрес: пустое окно или чужая
  вкладка хуже, чем ручной запуск;
* запись, по которой не из чего собрать команду.

Такие записи попадают в журнал для человека — с причиной и готовой командой для консоли.
Строку из журнала достаточно скопировать в консоль, чтобы получить нужное окно на своём
столе.

Приложение, помеченное «показывать на всех рабочих столах», второй раз не запускается, если
уже работает.

### 8.2. Перепроверка перед каждым запуском

Снимок окон для фазы A был снят раньше, а окна продолжают появляться. Поэтому перед каждым
запуском программа заново перечисляет окна и пробует сопоставить запись с окнами, которые
ещё ничьи, — по тем же правилам, что в фазе A.

Если нужное окно нашлось, второй экземпляр не запускается: окно просто ставится на место.
В отчёте появляется строка «уже открыто: …», а в сводке — «Уже было открыто (запускать не
понадобилось): N». Именно эта проверка (вместе с `settle-wait`) убирает дубли окон после
перезагрузки. Для браузерных записей окнам даётся ещё пара попыток прочитать адрес: пока
адрес неизвестен, сопоставление рискует прилепить запись к чужому окну.

### 8.3. Запуск идёт тремя шагами

Шаги разделены намеренно: некоторые приложения после появления сами выставляют своё окно
(восстанавливают собственное состояние) и переигрывают чужой перенос — окно остаётся посреди
экрана. Поэтому:

1. **Запустить всё, что нужно.** Подряд, не дожидаясь окон. Так общее время не складывается
   из ожиданий: приложения стартуют параллельно.
2. **Дождаться окон.** Для каждого запущенного приложения ждётся его окно. Предел ожидания
   считается **от момента запуска**, а не от входа в очередь: приложения стартовали все
   сразу, и пока ждали окна предыдущих, это окно уже получило своё время. Общий запас —
   шестьдесят секунд на всю очередь, а не по шестьдесят на каждую запись.
   * окно апплета панели управления ждётся десять секунд: его диалог появляется сразу после
     старта или не появляется вовсе;
   * ожидание прекращается досрочно, только если процесс завершился — тогда окна не будет
     никогда (в отчёте «приложение завершилось, не открыв окна»);
   * у браузера окно ищется по адресу страницы (до двадцати секунд), потому что окно
     восстановленной сессии того же класса ничем не отличается от нового;
   * перед переносом окна браузера программа ждёт, пока адрес страницы станет непустым и
     перестанет меняться (до тридцати секунд): тащить окно в момент навигации — спешка, без
     которой можно обойтись;
   * окна, которые приложение открыло «лишними» (например, пустую «новую вкладку» браузера),
     закрываются: в слепке их нет, а на текущем столе они остались бы висеть.
3. **Поставить окна на место.** Сначала программа ждёт, пока прямоугольники запущенных окон
   перестанут меняться (две секунды тишины, но не дольше двенадцати), и только потом ставит
   геометрию и целевой стол — уже знакомым порядком из фазы A.

Окна одного запуска не «воруют» окна другого: приложения стартовали одновременно, и две
записи одного приложения иначе могли бы поменяться окнами.

### 8.4. Права: обычные и администраторские

У каждой записи есть пометка «окно было открыто от администратора» (раздел 4, шаг 5).

* **Обычный `restore`** такие записи не поднимает вовсе: спрашивать UAC на каждое приложение
  было бы хуже, чем один раз показать готовую команду. Запись уходит в журнал с причиной
  «требуется повышение прав», в отчёте появляется «не запускаем: окно было открыто от
  администратора», а в конце — подсказка запустить `restore` от имени администратора.
* **Повышенный `restore`** (ярлык «от имени администратора», повышенная консоль, задача
  Планировщика с повышенными правами) поднимает такие записи своим администраторским
  токеном, а все остальные — токеном рабочего стола, то есть с обычными правами. Иначе
  получился бы второй «администраторский» Проводник, браузер не увидел бы профиль
  пользователя, а приложения из Microsoft Store не активировались бы.
* Если оболочка сама повышена (UAC выключен, пользователь — администратор), взять обычный
  токен неоткуда: программа сообщает об этом и не поднимает приложения администраторскими
  молча.

В подробном режиме видно, какой способ получения обычных прав сработал: «токен оболочки
(не повышен)» или «система отказала, запускаю запасным способом». Код 1314 в журнале при
обычном запуске — **нормальное** явление: он означает, что у процесса нет права создавать
процесс от имени другого пользователя, и программа сразу переходит к запасному способу.

## 9. Фаза C: порядок наложения

У каждого окна в слепке есть номер в порядке наложения: нулевой — самое верхнее. После того
как окна расставлены и перенесены, программа поднимает их по одному в порядке убывания
номера: сначала самые нижние, последним — самое верхнее. Так верхним в итоге остаётся то же
окно, что и при сохранении.

Поднятие идёт без активации: фокус не отбирается, курсор и текущая работа не страдают.
Окна, которые применить не удалось, в этой фазе не участвуют. В сводке видно, сколько окон
получило порядок: «z-order выставлен: N».

## 10. Итоги, проверка и код возврата

В конце считаются и печатаются итоги:

* «Применено» — сколько окон поставлено на место;
* «перенесено на другой десктоп» — сколько из них сменило стол;
* «z-order выставлен» — сколько окон получило порядок наложения;
* «Уже было открыто» — сколько приложений не понадобилось запускать (их окна нашлись сами);
* «Запущено / не удалось поднять / не запускается» — итоги фазы B;
* «Оказалось на десктопе 0» — сколько окон уехало на первый стол, потому что их сохранённых
  столов в системе нет. Отдельно бывает «на десктоп 0 увезти не удалось» и «десктоп не
  проверен (окно недоступно)» — это разные вещи, и путать их в отчёте нельзя;
* «не удалось восстановить» — сумма неудач применения и запуска.

Если сохранённых столов нет, печатается предупреждение с советом пересохранить раскладку
после возврата столов. В `--dry-run` та же величина показывается как «уехало бы на десктоп 0»:
можно заранее увидеть, сколько окон пострадает.

Код возврата у `restore`:

* **0** — всё применилось;
* **1** — работа сделана, но восстановлено не всё: часть окон не применилась, часть не
  поднялась, часть уехала на десктоп 0, либо в журнале для человека остались записи (значит,
  окно осталось за человеком — из-за прав, консоли или браузера без адреса);
* **2** — нет слепка или он битый;
* **3** — не удалось получить список виртуальных столов;
* **5** — служебной команде не хватило прав администратора;
* **6** — перенос между столами невозможен: внутренний интерфейс оболочки не прошёл
  проверку (другая сборка Windows);
* **64** — неверная командная строка.

Код 1 — это не «сломалось», а «сделано столько, сколько можно было»: смотреть надо на строки
выше и на журнал.

### 10.1. Журнал для человека

Часть окон восстановить программно нельзя: окно приложения, запущенного от администратора,
не двигается из обычного процесса; консоль без аргументов не перезапускается; браузер без
адреса не открывается. Всё это попадает в отдельный журнал рядом с программой, и строка
журнала — это **готовая команда для консоли**, а не описание проблемы. Причины и заголовки
печатаются в отчёте, а не в журнале: журнал нужен для копирования, отчёт — для чтения.

Причины записей:

* «перенести окно не удалось» — три попытки не помогли;
* «окно от администратора» — двигать его из обычного процесса нельзя;
* «требуется повышение прав» — приложение не запустилось или помечено как администраторское;
* «запуск не удался» — процесс не стартовал или окно не удалось расставить;
* «окно не появилось» — процесс запущен, но окно не появилось за отведённое время;
* «браузер без адреса» — запуск открыл бы пустое окно;
* «консоль» — содержимое неизвестно;
* «не из чего собрать команду».

Журнал описывает **только последний запуск**: он перезаписывается целиком, а если записей не
появилось, старый файл удаляется. Пишется он так, чтобы кириллица читалась в любом
редакторе. Если записи есть, журнал открывается в блокноте; открытое окно блокнота от
прошлого раза предварительно закрывается, чтобы на экране всегда было одно окно — со свежим
содержимым, а не с прошлой сессией.

В `--dry-run` журнал не пишется: режим ничего не меняет, и подсказывать «сделайте руками»
нечего.

## 11. Права и UAC

Обычные `save` и `restore` прав администратора не требуют: они двигают окна того же
пользователя. Сама программа повышения не просит, поэтому UAC при запуске не спрашивает.

Если Windows спрашивает разрешение **каждый раз**, значит на программе стоит флаг
совместимости «запускать от имени администратора» (галочка в свойствах или флаг в реестре
текущего пользователя). Программа замечает это и печатает готовую команду, снимающую флаг:
иначе пользователь видит только запрос UAC и не понимает его причину. Тот же флаг может
стоять на ярлыке — в реестре его не видно, но программа всё равно сообщает, что запущена
повышенной, и что обычные приложения будут запущены с обычными правами.

Повышение обязательно только трём служебным командам: `AutoSave`, `AutoRestore` и
`Uninstall`. Их и запускают «от имени администратора» — Планировщик заданий не даёт менять
свои задания обычному пользователю.

## 12. Автозапуск: `AutoSave`, `AutoRestore`, `Uninstall`

Автозапуск ставится не сам, а тремя командами — когда пользователь этого захочет. Всё через
Планировщик заданий, от имени текущего пользователя, без пароля: поэтому Windows не
спрашивает пароль каждые десять минут.

* `AutoSave` — задача «сохранять каждые N минут». Интервал берётся из переменной `AutoSave`
  (минуты, по умолчанию десять, допустимо от одной до суток). Значение читается **в момент
  создания задачи**: поправили настройку — выполните команду снова, задача перезапишется.
  Задача запускает `save` в скрытом режиме.
* `AutoRestore` — задача «восстановить при входе в систему». Задержка берётся из переменной
  `AutoRestoreDelay` (секунды, по умолчанию тридцать, допустимо от нуля до часа). Задержка
  нужна, чтобы приложения из автозагрузки успели открыть свои окна сами: иначе программа
  поднимет их сама, а потом приложение откроет второе окно. Меньше двадцати секунд ставить
  смысла нет. Задача запускает `restore` в скрытом режиме.
* `Uninstall` — снимает обе задачи и значение автозагрузки в реестре, если его ставили
  вручную. Если автозапуск не был установлен, так и говорит: «снимать нечего».

Сами задачи работают с обычными правами: администратор нужен только на момент установки и
снятия задач. Поэтому автовосстановление после перезагрузки ведёт себя как обычный `restore`:
приложения поднимаются от обычного пользователя, а то, что требует повышения, попадает в
журнал для человека.

С ключом `--dry-run` эти команды ничего не меняют: показывают, какая задача была бы создана
(расписание, файл с описанием задачи, готовая команда ручной регистрации) или что именно
найдено и было бы снято. Проверить это можно и без прав администратора.

С ключом `--hidden` программа прячет окно консоли и не ждёт нажатия клавиши — так её и
запускают задачи. В скрытом режиме журнал диагностики ведётся всегда: иначе ошибка фонового
запуска пропала бы молча.

Коды возврата у служебных команд: 0 — задача поставлена (или снята) и проверка прошла,
1 — Планировщик отказал, 5 — не хватило прав администратора, 64 — неверная командная строка.

## 13. Осмотр без изменений: `--list`

`--list` ничего не сохраняет и не меняет — печатает то, что программа видит прямо сейчас:

* виртуальные столы: номер, идентификатор, имя, пометка «текущий» и источник сведений;
* приложения, помеченные «показывать на всех рабочих столах», — с путём, идентификатором
  приложения или папкой;
* окна, сгруппированные по столу и в порядке наложения: «накрытость», состояние, номер
  процесса, программа, координаты, класс, заголовок; для окон Проводника — папка, для
  свёрнутых и развёрнутых — «нормальная» позиция отдельной строкой;
* если слепок есть — карту «стол из слепка → стол сейчас», то есть главный способ проверить
  сопоставление столов, ничего не перемещая.

Предварительная программа (`prelaunch`) при `--list` не запускается: осмотр системы ничего
не меняет.

## 14. Подробный режим: `--verbose`

Подробный режим включает журнал диагностики и добавляет в вывод то, что нужно при разборе:

* полный путь к программе, командную строку и идентификатор приложения у каждого окна;
* адреса страниц, прочитанные у живых браузеров;
* пары «запись ↔ окно» с числом баллов и признаками совпадения;
* ход ожидания «успокоения» и ход перепроверок («уже открыто»);
* что именно изменилось при сравнении слепков (причина перезаписи файла);
* итог самопроверки после сохранения;
* строки о правах: удалось ли включить привилегии и каким способом получены обычные права.

Журнал диагностики пишется и без подробного режима, если программа запущена скрыто, — иначе
ошибку фоновой задачи негде было бы увидеть. Если отдельного быстрого диска нет, журнал
пишется рядом с программой: утилита остаётся переносимой.

## 15. Чего программа не делает

* Не управляет приложениями: она не закрывает и не перезапускает то, что уже работает, а
  только расставляет окна. Исключение — пустые окна, которые браузер открыл сам при старте:
  их программа закрывает, потому что в слепке их нет.
* Не восстанавливает содержимое консоли: в командной строке окна лежит только команда
  оболочки, а что было запущено внутри, системе неизвестно. Консоль с аргументами
  повторяется, консоль без аргументов уходит в журнал.
* Не читает адрес страницы, если браузер закрыл доступ к средству доступности: запись
  сохранится без адреса и при восстановлении не запустится (это лучше пустого окна).
* Не двигает окна приложений, запущенных от администратора, если сама запущена обычным
  образом: так устроена Windows, и обходного пути нет — есть только журнал с командой.
* Не работает с окнами других пользовательских сеансов и с окнами, которые приложение
  успело создать в момент перечисления: такие окна либо попадут в следующий слепок, либо
  будут найдены перепроверкой перед запуском.
* Не обещает одинакового результата на другой сборке Windows, если внутренний интерфейс
  оболочки для переноса окон там устроен иначе: программа это проверяет и честно
  останавливается до первого изменения (код 6), а не делает вид, что всё хорошо.

## 16. Сводка: команды и настройки

Команды командной строки:

```
save                     записать текущую раскладку в слепок
restore                  восстановить раскладку из слепка
restore --from <файл>    восстановить из указанного слепка (рабочая версия,
                         «вчерашний день», «прежняя конфигурация»)
restore --dry-run        показать план, ничего не меняя
AutoSave                 поставить задачу «сохранять каждые N минут»
AutoRestore              поставить задачу «восстановить при входе в систему»
Uninstall                снять задачи и значение автозагрузки
--list                   показать столы, приложения «на всех столах» и окна
--verbose                подробный журнал диагностики
--hidden                 скрыть консоль и не ждать клавишу (для задач)
--help, /?               справка
--version                версия
```

Сочетания: за запуск — ровно одна команда; `--from` — только с `restore`; `--dry-run` — с
`restore`, `AutoSave`, `AutoRestore`, `Uninstall`; `--hidden` — только с командой;
`--list`, `--help`, `--version` между собой и с командами не сочетаются.

Переменные настроек:

```
prelaunch=<путь>         программа, которую надо запустить и дождаться закрытия её окна
                         перед восстановлением (только restore)
prelaunch-args=<строка>  аргументы для неё
prelaunch-timeout=<сек>  сколько ждать её окно; 0 — без ограничения
AutoSave=<минуты>        интервал задачи AutoSave (1…1440, по умолчанию 10)
AutoRestoreDelay=<сек>   задержка задачи AutoRestore после входа (0…3600, по умолчанию 30);
                         используется и как пауза после раннего запуска браузеров
Layouts=<число>          сколько рабочих версий слепка хранить (1…20, по умолчанию 3)
settle-wait=<сек>        сколько ждать «успокоения» окон перед запуском (0…600,
                         по умолчанию 10; 0 — не ждать вовсе)
```

Настройки читаются при каждом запуске, файл необязателен. Незнакомые переменные не мешают:
в подробном режиме они просто попадают в журнал, поэтому в настройки можно добавлять свои
пометки и заготовки.
